### なぜこの見た目・構成にしたか

作っているときに決めたことを、決めた理由ごと書いています。

1. **ホームを「今日の1品」の即答画面にした**
   要件定義で一番の穴だと判定したのが「21時に帰ってきて冷蔵庫の前で立ち尽くす時間」への答えが無いことだった。レシピを探させる画面ではなく、開いた瞬間に1品を出す画面をホームに据え、これを MVP の必須機能として入れ直した（2026-06-13 決定）。

2. **写真投稿とコメント機能を入れなかった**
   ユーザーの動機を4層に分けて採点したとき、「自炊できる人に見られたい」という見せたい欲だけが明確に弱かった。弱い動機に機能を足しても使われないので、写真投稿・コメント・栄養計算・アプリ内課金はまとめて初版から外した。

3. **「このままだと危ない」と脅す言い方をしない**
   悩みの深さを5段階で2、頻度を5と見積もった。深刻さを煽ると実態と合わない売り方になるので、軽く・毎日触れる方向に全部寄せた。画面の文言もその基準で書いている。

| 課題 | 転職サービスが掲げる求人数や評判の数字が、どこまで本当か誰も数え直していない。 |
| 自分の役割 | サイト設計・記事構成・実装・公開・検索順位と流入の計測まで 1人。 |
| 期間 | 2026-08-12 に最初の記事を公開。以後更新中（2026-10-12 時点）。 |
| 結果 | 最初の記事の公開日 2026-08-12<br>公開記事 60本（2026-10-12 時点）<br>Astro ＋ Cloudflare Pages。サーバー費用 0円 |
| 学んだこと | 記事を増やすより、検索から来た1ページを直すほうが数字が動いた。毎日「今日触る1ページ」を機械に決めさせている。 |

### なぜこの見た目・構成にしたか

作っているときに決めたことを、決めた理由ごと書いています。

1. **記事の形を、書き手の裁量ではなく型で固定した**
   世間で言われている数字、実際に数えた結果、そこから先は分からないこと、の3段の並びと、出典（URLと取得日）の添付を、記事ファイルの必須項目として機械が強制する形にした。型があるので、記事を1本も書き直さずに見せ方だけを全記事へ反映できる。

2. **本文の数字を手で打てないようにした**
   記事の中の数値はデータベースから差し込む書き方にし、手打ちの数字を見つけたら検査が通らないようにした。数字を扱うサイトで一番こわいのは、直したつもりの古い数字が1箇所だけ残ることだった。

3. **「全文はこちら」と書かないことにした**
   要点だけ読んで離脱されるのは避けられない。なので要点の枠には毎回、その記事にしか無い会社ごとの数字表への案内を入れている。誘い文句ではなく、中身の名前で呼ぶ。

| 自分の役割 | サイト設計・公的データの収集と検査の仕組み・実装・公開・計測まで 1人。 |
| 期間 | 2026-09-21 着手 → 2026-09-23 公開（3日）。以後更新中（2026-10-12 時点）。 |
| 結果 | 着手 2026-09-21、公開 2026-09-23（3日）<br>国と自治体の公表データから 561ページを生成（2026-09-22 の初回デプロイ時の実測）<br>Astro ＋ Cloudflare Pages。サーバー費用 0円 |
| 学んだこと | 3本目は記事を書く形をやめ、公表データの1行から1ページを組み立てる形に変えた。同じ型を移すときも、題材によっては作る単位から変える必要がある。 |

### なぜこの見た目・構成にしたか

作っているときに決めたことを、決めた理由ごと書いています。

1. **公表されていない数字で割り算をしなかった**
   「入るまで何年待つか」を出すには、1年に何床空くかが要る。国も自治体もこの数を公表していない。仮の数を置いて掛けた時点で、それは公的データではなくサイトが作った数字になるので、公表されている2つの実数の割り算までで止めた。

2. **同じ計算式を、わざと2か所に別々に書いた**
   費用の計算式を、サイトが使う側と検査が使う側に別々に書いてある。片方だけ直して片方を忘れると数字がずれるので、ずれたら検査で気づける。突き合わせは250通りの組み合わせで行っている。

3. **言えることが少ないページは、検索に出さないことにした**
   施設ごとのページは、公表データから言えることが3項目に届かなければ検索エンジンに登録しない設定で公開した。判定は人ではなくデータベースの値で行い、登録しないページがサイトマップに混ざっていないかもビルド後に機械で確かめている。

3. **自分の閲覧を数えない仕組みを、公開の前に入れた**
   自分で動作確認するたびに訪問者が1人増える。別のサイトで、28日間の訪問の8割が自分の確認だったことがあった。本番のURL以外では計測を送らない仕組みと、自分の端末に印を付ける仕組みを公開前に入れた。後から入れても、それまでのデータは戻らない。

### なぜこの見た目・構成にしたか

作っているときに決めたことを、決めた理由ごと書いています。

1. **AI は候補を出すだけで、確定は人がする**
   指摘はすべて「候補」として出し、担当者が採用・編集・却下してから返す流れにした。指摘にはオリエンのどの条件が根拠かを必ず付け、出典が見つからない引用は採用せず「要確認」に回す。指摘が出なかっただけの項目を合格扱いしない、とも決めている。

2. **返す形を、Office のコメント機能ではなく列とスライドの追加にした**
   最初は Office のコメント機能に書き込む設計だったが、2026-10-12 に、Excel は該当行の右に「指摘」列を1列、PowerPoint は末尾に指摘一覧のスライドを足す形（こちらは仮）へ変えた。Office の版を問わず開けて、既存のセル・数式・書式には触らずに済む。

3. **原本は書き換えず、コピーに書き足して返す**
   返すのは原本のコピーに書き足したファイルで、原本はそのまま残す。オリエンが更新されても過去のチェック結果は書き換えず、どの版の基準で照合したかを結果ごとに固定している。
